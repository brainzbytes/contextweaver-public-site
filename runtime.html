Run lifecycle

The simple view of a rigorous execution model.

The full design contains more granular authorization, retrieval, binding, checkpoint, disclosure, and audit states; users see a comprehensible progression.

Receive and scrutinize intent

Resolve identity, tenant, roles, relationships, device, purpose, risk, classification, entities, ambiguity, and candidate outcomes.

Select or constrained-compose

Choose an approved Service, ask a clarifying question, or propose a graph from only admitted capabilities and control nodes.

Compile and authorize the complete graph

Validate schemas, field bindings, dependencies, fallback sets, budgets, RAG scopes, model envelopes, tool risk, and approvals.

Freeze the immutable plan

Pin exact Service, Workflow, Agent, MCP, model, policy, schema, source, index, and configuration versions.

Commit the durable run

Persist state, the plan, first tasks or approval request, and transactional outbox before returning acceptance.

Execute typed work

Dispatch through persistent commands; run ready Agents in parallel; use bounded context; checkpoint accepted artifacts.

Invoke tools under delegated authority

The MCP gateway validates the exact call, performs just-in-time token exchange, keeps credentials outside the Agent, and records receipts.

Finalize, disclose, and prove

Validate one canonical result, apply disclosure policy and approval, render approved formats, persist evidence, and reauthorize delivery.

Resilience by design

Long-running work can wait, retry, resume, and compensate.

Durability is a product contract rather than a best-effort property hidden inside an Agent loop.

Durable waits

Release compute while waiting

Human approval, timer, callback, or external event state is persisted. The run resumes from authoritative state rather than holding an open process.

At-least-once safety

Replay without repeating side effects

Inbox/outbox, leases, idempotency keys, accepted artifact hashes, and provider receipts let another worker safely continue after failure.

Saga compensation

Handle partial business failure

Each side effect declares whether and how it can be compensated. Failed plans reverse approved actions or escalate explicit non-compensable state.
